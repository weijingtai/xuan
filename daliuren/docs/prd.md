
# 产品需求文档 (PRD) - 大六壬排盘App

## 1. 引言

### 1.1. 项目愿景
本项目旨在开发一款专业、准确、易于使用的大六壬排盘应用。它能够根据用户输入的时间或干支信息，快速生成完整的大六壬课式，并提供相关的经典断语参考，为大六壬数术研究者和爱好者提供一个便捷、高效的数字化工具。

### 1.2. 目标用户
-   大六壬数术的专业研究人员和从业者。
-   对中国传统数术文化感兴趣的学生和爱好者。
-   需要快速排盘以进行案例分析和学术交流的用户。

---

## 2. 功能需求

### 2.1.核心功能

#### 2.1.1. 按时间起课
-   **描述**: 用户可以通过选择公历日期和时间，自动生成对应的大六壬课式。这是应用最核心和最常用的功能。
-   **输入**:
    -   公历年、月、日、时、分。
    -   提供“当前时间”快捷按钮，一键获取设备当前时间。
-   **输出**: 生成完整的大六壬盘面。
-   **验收标准**:
    -   应用能够正确处理不同时区和夏令时，确保取用的干支准确无误。
    -   选择时间后，能立即进行排盘。

#### 2.1.2. 按干支起课
-   **描述**: 允许专业用户通过手动输入特定的日干支、时干支、月将、阴阳遁等信息来生成课式，用于研究特定的、非实时的课例。
-   **输入**:
    -   日干支（必选）。
    -   时干支 或 局数（二选一）。
    -   阴阳遁（必选）。
-   **输出**: 生成完整的大六壬盘面。
-   **验收标准**:
    -   输入合法参数后，能准确生成对应的盘面。
    -   当缺少必要参数时，界面应有明确提示（如输入框抖动）。

### 2.2. 盘面展示
-   **描述**: 清晰、直观地展示大六壬课式的全部关键信息。
-   **核心要素**:
    -   **天地盘**: 准确展示十二地支、月将、贵人等信息。
    -   **四课**: 完整展示四课的结构，包括干支、寄宫、神将。
    -   **三传**: 完整展示初传、中传、末传，包括地支、六亲、神将、遁干。
    -   **课体信息**: 显示课体名称（如“元首课”、“重审课”等九宗门信息）。
    -   **基本信息**: 公历和农历时间、四柱（八字）、节气、月将、空亡等。

### 2.3. 课体分析与断语
-   **描述**: 根据生成的课式，从内置的知识库中检索并展示相关的经典断语和释义。
-   **数据来源**: 《御定大六壬》等经典文本。
-   **展示内容**:
    -   **课体名称**: 例如“甲子日第一局，干上子”。
    -   **课义**: 对当前课体的总体解释。
    -   **解曰**: 进一步的阐释。
    -   **断曰**: 吉凶判断。
    -   **毕法赋等**: 相关的经典条文。

## 3. 技术架构概述

### 3.1. 框架
-   应用基于 **Flutter** 框架开发，可跨平台部署到 iOS、Android 及 Web。

### 3.2. 核心逻辑实现
-   本应用的核心逻辑采用**查表法**实现，而非实时算法演算。
-   **数据源**: 所有课式和断语都预先计算和整理，并存储在应用内的 `assets` 目录下的 **JSON 文件**中。
-   **执行流程**: 应用根据用户输入的参数（时间或干支）组合出查询键，从对应的 JSON 文件中检索出完整的盘面数据模型和断语，然后渲染到UI上。
-   **优势**:
    -   **性能高**: 查表速度远快于复杂计算，能实现盘面的瞬时加载。
    -   **可靠性强**: 避免了复杂算法在边缘情况下可能出现的错误，保证了结果与数据源（如《御定大六壬》）的绝对一致。
    -   **易于维护**: 更新或修正断语只需修改 JSON 文件，无需改动代码逻辑。

### 3.3. 代码结构
-   项目采用模块化结构，`daliuren` 作为主应用模块，依赖于 `common` 共享库。
-   `common` 包提供了项目通用的基础能力，如：
    -   **数据模型**: 天干、地支、五行、节气等枚举（Enums）。
    -   **常量资源**: 颜色、数字格式化等静态映射。
    -   **通用组件**: 四柱八字、节气标签等可复用的 Widget。

---

## 4. 非功能性需求

### 4.1. 性能
-   应用启动和排盘响应应在1秒内完成，确保流畅的用户体验。

### 4.2. 离线能力
-   由于所有数据和逻辑都打包在应用内，应用必须能够**完全离线**使用。

### 4.3. 平台兼容性
-   首期目标为 iOS 和 Android 平台，后续可扩展至 Web。
