# 皇极取数法重构为MVVM+UseCase架构 - 对齐文档

## 项目特性规范

### 现有架构模式
- **架构**: MVVM + UseCase 模式
- **状态管理**: ChangeNotifier + Provider
- **UseCase基类**: 
  - `BaseGetTiaoWenListUseCase<TParams>` - 普通条文列表计算
  - `BaseInteractiveUseCase<TParams>` - 交互式计算（支持用户参与）
- **ViewModel基类**: `BaseTiaoWenListViewModel`
- **异常体系**: 自定义异常继承体系
- **测试策略**: 单元测试 + 集成测试

### 业务域理解
- **皇极取数法**: 元会运世取数法，基于四柱计算条文数
- **核心特点**: 包含用户交互环节（规则5需要用户参与运算）
- **计算流程**: 多步骤计算，包含基础数调整逻辑

## 原始需求分析

### 当前实现 (real_case_7.dart)
- **类**: `TiaoWenNumberCalculationStrategy` (已标记@Deprecated)
- **功能**: 皇极取数法的完整计算逻辑
- **问题**: 
  1. 单一类承担过多职责
  2. 缺乏用户交互支持
  3. 未遵循MVVM架构
  4. 状态管理混乱

### 关键业务规则
1. **四柱配太玄数**: 年干+年支=元，月干+月支=会，日干+日支=运，时干+时支=世
2. **元会基本数**: 年+月互合成数顺左旋取数
3. **运世基础数**: 日+时互合成数逆右旋取数  
4. **主条文数**: 元会基础数 + 年干太玄数
5. **🔥用户交互点**: "次条文数为初刻数，如果符合则将此条文数作为基础数计算，如不符合则按照'30'递加或递减直到找到对应的"
6. **多条文计算**: 基于确定的基础数进行12种不同的条文数计算

## 需求理解

### 架构目标
1. **UseCase层**: 封装皇极取数法的业务逻辑
2. **ViewModel层**: 管理UI状态和用户交互
3. **交互式支持**: 处理规则5的用户参与运算
4. **异常处理**: 完善的错误处理和用户反馈

### 技术约束
- 必须继承现有的基类
- 遵循现有的命名约定
- 使用现有的异常体系
- 保持与现有测试框架的兼容性
